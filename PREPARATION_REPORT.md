# Dori Bakery preparation report

## Original project and fixes

The archive contained a bakery homepage with original artwork and video, category cards, a menu with database-backed search, account pages, a cart, favorites, checkout, an order confirmation, and a tracking page. The two supplied SQL exports defined the account and shopping tables. The homepage presented Coffee with images and copy, but the source supplied no priced coffee products. Its navigation now opens an availability note. Strawberry Cookie was already on the menu with its image, description, and price. Its missing database row was added using those exact details. The Matcha Tiramisu card now points to its existing catalog ID.

Search now binds the query and treats wildcard characters literally. Cart and favorite actions use product IDs, check the server response before showing success, and prevent duplicate rows for the same account and product. The original duplicate Fruit and Red Velvet rows remain in the import to preserve the supplied data. Each result uses its own ID, and the static category cards use the first matching IDs. The cart now applies the original demo discount on the server. The summary, checkout, and saved total use the same calculation, including the original $7 delivery fee. Tracking and confirmation are scoped to the signed-in account.

The original source compared and stored plaintext passwords, interpolated request data into SQL, printed some dynamic values directly, used a GET link to log out, and did not check CSRF tokens. It also used root database credentials in source, and the bundled legacy SQL contained user records. The portfolio copy uses bcrypt and `password_verify()`, parameterized queries, escaped output, session ID rotation, HTTP-only cookies with SameSite Lax, and CSRF checks on POSTs. Config lives in an ignored local PHP file, and Apache denies direct requests for SQL and configuration files. Checkout validates billing fields and the payment choice, locks cart rows, calculates totals using database prices, and writes the order and items and clears purchased cart rows in one transaction. A successful submission uses a one-time checkout token and redirects to a refresh-safe confirmation page.

## Files and database changes

- Modified the original PHP pages in `page/` and `video/mainpage.php` while retaining the original page structure and styles. Added shared session, form, and database helpers, a root index, config example, Git ignore rules, Apache access rules, and a virtual host example.
- Switched the navigation collapse controls to match the bundled Bootstrap 5 version and fixed path case for the font references. Kept the artwork used by the pages or catalog, the fonts, and both videos. Omitted duplicate archives, IDE and Finder metadata, unused assets, and older or unused JavaScript bundles. Replaced the footer’s original contact values with demo placeholders. Included the upstream license notices for [Bootstrap](https://github.com/twbs/bootstrap/blob/v5.3.3/LICENSE) and [Tanha](https://github.com/rastikerdar/tanha-font/blob/master/LICENSE).
- Used the separate schema-only authentication export and the supplied catalog export. Expanded the password column to 255 characters, aligned the email collation with the shopping tables, and made account emails unique. Added unique account-product keys for cart and favorites, a cart quantity constraint, and indexes and foreign keys for cart products, favorite products, and order items. Historical order lines retain their captured product name and price. The imports contain no account, cart, favorite, or order records.
- The default config uses `dori_login` and `dori_search_menu`. The table names and original database roles are preserved. These are clean setup scripts for the portfolio copy. A legacy account import would require separate password resets and duplicate cleanup.

## Tests performed

- PHP 8.2.4 lint passed for all 18 PHP files. Both SQL imports succeeded on a temporary MariaDB 10.4.28 instance using the XAMPP binaries. The fresh catalog had 25 rows and no users or orders.
- A temporary Apache 2.4.56 configuration passed its syntax check. HTTP tests resolved the homepage, menu, category anchors, and 50 linked local pages and assets under each of the XAMPP folder URL and `dori-bakery.localhost`. Requests for configuration, SQL, and test Git metadata were denied, including an encoded dot in the Git path.
- HTTP tests passed for registration, duplicate email rejection, bcrypt storage, failed and successful login, logout, session ID rotation, guest access restrictions, CSRF rejection, and account isolation. Search handled quotes, a literal wildcard, an HTML payload, and an unexpected array parameter.
- Cart additions, quantity changes, removal, favorites, the discount, billing validation, order confirmation, and tracking passed. The saved order used the signed-in account and trusted totals when the request supplied a different email and total. A deliberately failed item insert rolled back the order and preserved the cart. A retry succeeded, a replay created no duplicate, and two simultaneous checkouts from separate sessions produced one order for the same cart.
- In the in-app browser, the homepage rendered, the virtual-host menu returned results for Strawberry, and the guest cart button prompted sign-in. A decorative image was intercepting clicks on **order online**. After the fix, the link opened the menu, and an authenticated click added a cookie, showed a success message, and updated the cart badge.
- The imports were exercised with the MariaDB command-line client. The phpMyAdmin click-through, the live XAMPP Manager configuration, and a full cross-browser/mobile layout pass remain manual checks. The tests used fictional accounts in isolated data, with the original XAMPP databases left untouched.
